1. Почему в Git ветвление «дешёвое», а в SVN — «дорогое»?
   В Git ветка фактически представляет собой небольшой указатель на определённый коммит. При создании новой ветки Git не копирует весь проект, поэтому операция выполняется очень быстро и почти не занимает дополнительного места.

В SVN ветка традиционно создаётся как копия каталога проекта внутри репозитория, например из `trunk` в `branches`. Хотя SVN использует оптимизацию copy-on-write и физически не дублирует все файлы сразу, работа с ветками всё равно сильнее завязана на структуру центрального репозитория и сервер. Поэтому ветвление в SVN обычно считается более «тяжёлым» организационно и менее удобным для частого создания короткоживущих веток.

2. Можно ли в SVN сделать коммит без интернета? Почему?
   Обычно нет. SVN является централизованной системой контроля версий. Основная история проекта хранится на центральном сервере, и команда `commit` должна отправить изменения именно туда.

Без соединения с сервером пользователь может продолжать изменять локальные файлы, просматривать часть локальной информации и готовить изменения, но создать полноценный новый коммит в истории SVN не получится.

В Git ситуация другая: репозиторий и вся его история находятся локально, поэтому коммиты можно делать без подключения к сети, а позже отправить их на удалённый сервер.

3. В каких сценариях SVN до сих пор может быть предпочтительнее Git?
   SVN может быть удобнее в проектах, где требуется строгая централизованная модель работы и единый сервер считается главным источником данных. Например:

* когда нужен простой централизованный контроль доступа к отдельным каталогам репозитория;
* при работе с большим количеством бинарных файлов, особенно если используется блокировка файлов перед редактированием;
* в организациях, где уже существует большая инфраструктура на SVN и переход на Git не даёт достаточной выгоды;
* когда разработчикам не требуется сложное ветвление и распределённая работа;
* в некоторых корпоративных проектах с жёстко установленным процессом работы через центральный репозиторий.

Таким образом, Git лучше подходит для активного ветвления, распределённой разработки и автономной работы, а SVN может оставаться удобным для простых централизованных процессов и проектов со строгим контролем файлов.
